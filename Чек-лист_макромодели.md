# Долгопрудный — пять задач до первого прогноза

**Цель** — собрать `model_input.json`, запустить `model.py` и получить первый городской `flows.csv`. Семь зон уже готовы в `zones_primary.geojson`. Новые полевые замеры для этого прогона не нужны. Координаты створов берём из `points.csv`, открытые интенсивности — из `calibration.csv`.

| Что делать | Откуда брать данные и как действовать | Что передать лиду |
|---|---|---|
| **1. Подготовить рёбра и привязать замеры** · сеть | Открыть `osm_data/roads.gpkg` в QGIS или загрузить `osm_data/roads.graphml` в Python. Взять длину, направление, класс `highway`, а где есть — `maxspeed` и полосы. Для первого прогона при пропусках использовать **явные стартовые допущения** по классам. Например, 50 км/ч для магистральных, 35 для улиц-связок и 25 для местных. Для черновой пропускной способности можно взять 900 авто/ч на полосу и проверить чувствительность позже. На двусторонней дороге проверить, как общее число полос делится по направлениям. Время ребра в секундах = 3,6 × длина в метрах / скорость в км/ч. Для каждого ID из `points.csv` выбрать ребро по координатам, названию и направлению. Начать с P02A, P02B, P08A, P14B. Для проверки сомнительных дорог соберите `osm_map_wide.html` по инструкции в `Запуск_MVP.md`. | `edges` с полями `id,u,v,time_s,capacity_vph` и `point_edges` с 30 ID. Если точка попала на развязку, сохранить скриншот выбора. Складывать потоки можно по параллельным проезжим частям в одном направлении, если они пересекают один створ. |
| **2. Подключить семь зон и три внешних коридора** · районирование и сеть | Открыть `project_boundary_map.html` и граф. Для каждого из семи полигонов выбрать узел выезда и узел въезда на реальном подъезде к застройке. Сначала разобрать Водники, МФТИ и ДНПП. Для E1–E3 проверить, где **фактически** пересекают `area.csv` дороги в коридорах Лихачёвского проспекта, Московской улицы у Водников и Долгопрудненского шоссе. P02, P03 и P06 помогают найти эти дороги, но координаты створов и ворот могут различаться. Построить по одному маршруту в обе стороны между каждыми воротами и жилой зоной. Если граф не пропускает реальный подъезд, сверить его в `osm_data/dolgoprudny_wide.osm` и добавить разрешённый проезд. | `zones` с полями `departure,arrival` и `external: true` для ворот. Для каждого узла записать название улицы или въезда, по которому можно проверить выбор. |
| **3. Сделать первую оценку спроса** · спрос | Взять здания из `osm_data/features.geojson` и распределить их по семи зонам из `zones_primary.geojson`. Для **весов отправлений** сложить площадь жилых зданий × этажность, где она известна. Для пропусков взять медиану по зданиям того же типа и записать правило. Для **весов прибытий** отдельно собрать в том же файле предприятия, офисы и учебные объекты. МФТИ, ДНПП и лицей Капицы вынести отдельными строками. Если есть численность работников или учащихся, использовать её с явными допущениями о доле приезжающих утром на автомобиле. Если её нет, начать с площади или числа объектов как относительного веса. Для абсолютного масштаба записать стартовый сценарий отдельно от весов. Например, если P02 подходит как приближение южных ворот, возьмите два направления P02 из файла курса и для стартового сценария разделите каждый часовой замер поровну между двумя получасами. Для двух других ворот и внутренних поездок открытых чисел нет. Задать явно базовые объёмы и диапазоны, например как доли от южного потока, и прогнать сценарии. Не суммировать камеры P02, P08 и P14 для оценки числа уникальных поездок. | `periods` с четырьмя периодами и двумя словарями на период, `departures` и `arrivals`. Единица — **машин за получас**. В каждом периоде суммы совпадают. Рядом хранить табличку «число → источник или допущение». Если запрещаем транзит между внешними зонами, отдельно проверить, что внутренние зоны могут принять все внешние отправления и обеспечить все внешние прибытия. |
| **4. Запустить и проверить первый прогноз** · лид | Собрать блоки `edges`, `point_edges`, `zones`, `periods` в `model_input.json` по формату из `Запуск_MVP.md`. Запустить `python model.py model_input.json`. При ошибке балансировки начать с сумм спроса и доступности пар. При нулевом потоке на открытой камере сначала проверить направление, выбранное ребро и маршруты, которые должны его пересекать. | Первый `flows.csv` до калибровки. В нём 30 ID, четыре получаса, 120 конечных неотрицательных значений в авто/ч. Записать, сошёлся ли расчёт по каждому периоду. |
| **5. Сравнить с камерами и подготовить предзащиту** · лид | Сопоставить восемь значений из `calibration.csv` с прогнозом. Для каждого часа усреднить две получасовые интенсивности из `flows.csv`. Например, 3000 и 3200 авто/ч дают 3100 авто/ч за час. Сначала устранить ошибки привязки и единиц. Затем поменять один объяснимый параметр, например общий масштаб спроса или объём на южных воротах, и сравнить GEH до и после. | Таблица «ID, час, наблюдение, прогноз до, прогноз после, GEH», параметры запуска и одна версия `flows.csv` для проверки по закрытым данным. Перед отправкой другой участник повторяет запуск из тех же файлов. |

**С чего начать сегодня** — сеть привязывает четыре открытых направления, районирование отмечает въезды и подъезды, спрос считает веса по семи зонам. Эти три задачи можно делать параллельно.
